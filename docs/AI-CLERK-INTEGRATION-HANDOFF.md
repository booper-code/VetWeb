**Snapshot: 2026-11-21.** Resume in the current working directory on `main`. The worktree contains unrelated uncommitted changes; preserve them. Nothing from this assistant work was committed, pushed, or deployed. This is a design and local implementation handoff, not approval for a live model, paid calls, production data, or a hosted rollout.

## What the user wants

- A normal conversational chat experience, including greetings, natural clinic questions and useful follow-ups, with a large animated popup that minimizes back to the top-bar **AI Assistant** button.
- Chat history like a web AI, and OpenCode-like efficiency: a quick path for straightforward questions, bounded context and a small set of purpose-built tools. Do **not** embed the OpenCode coding-agent runtime.
- The Clerk must only see the clinic information the signed-in user is allowed to see and that is explicitly made available to it. Do not give it unrestricted queries or write access. Rescheduling stays a proposal for manual review and save.
- `http://localhost:3000` is the canonical test URL. Its ignored `.env.development.local` targets isolated `vetcloudpro-staging-6f819b`, not shared `vetcloudpro`; use fictional records. `NEXT_PUBLIC_CSV_IMPORT_RECEIPTS=0` here because isolated deployed rules lack that optional collection. Use the OpenCode Review tab for shared debugging; the user enters credentials privately.

## Foundation decision from Hy4 Flash High

- **Recommended:** [Vercel AI SDK](https://github.com/vercel/ai) ([Apache-2.0](https://github.com/vercel/ai/blob/main/LICENSE)) for provider adapters, schema-constrained output, and [mock model tests](https://ai-sdk.dev/docs/ai-sdk-core/testing). The dependency does not enforce clinic permissions. No dependency has been added; verify compatible pinned versions and Worker runtime support before selecting APIs. A first-party Cloudflare Worker is the candidate for an eventual server endpoint because the hosted Next.js app is a static export.
- **Borrow later:** [Cloudflare Agents](https://github.com/cloudflare/agents) ([MIT](https://github.com/cloudflare/agents/blob/main/LICENSE)) for scoped persistence and history pruning patterns. Durable Objects are optional, not a requirement for the first prototype. Persistent history needs an explicit per-user/per-clinic retention, deletion and access design before adoption.
- **Do not embed** [OpenCode](https://github.com/anomalyco/opencode) or [LangGraph JS](https://github.com/langchain-ai/langgraphjs) for this slice. Borrow bounded context and explicit transitions, not the coding tool surface or a general agent loop.
- Keep a zero-model fast path. For unknown phrasing and bounded follow-ups, test an optional **single structured model proposal** behind an adapter. Treat it as untrusted: validate intent and arguments, recheck clinic membership and feature access, dispatch only fixed read-only capabilities, and render clinic facts from verified results. Unknown or ambiguous requests should clarify. Do not send raw live prompts, names, records, transcript, or credentials to an external model; free text itself can contain identifiers. The first pilot uses fictional input and an in-process mock only.

## Mock follow-up prototype

- After a verified fictional count, “Does that include services?” explains the catalog without a read; “Can you check again?” performs one fresh scoped count. The mock sees only an allowlisted fictional phrase and one topic tag, never counts, clinic identifiers, patient records or transcript text. Other phrasing is not inferred; this is not a general-conversation accuracy benchmark and does not use the Phase 2B holdout.
- Fixture assertions check zero model calls on the deterministic path, one on an eligible fallback (no retries), zero or one catalog read per turn, and no writes. Ambiguous and mixed requests, malformed or overbroad plans, missing permission, and stale scope fail closed. Explicit rescheduling remains deterministic and draft-only; contextual commands cannot reschedule.
- Use the **Vercel AI SDK** as the basis for a future provider adapter and structured-output test doubles, not as the permission layer. No SDK release or runtime API was selected for this offline slice and no dependency was added. Before a Worker experiment, verify a pinned SDK version in that runtime and keep the same narrow proposal validation and scope checks.
